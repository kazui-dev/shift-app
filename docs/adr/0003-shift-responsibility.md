# 0003 全体権限とシフト責任者の範囲を分ける

- 状態：採用
- 決定記録日：2026-09-11
- 実装状況：刷新内容は未実装

## 背景

全体で配置する運用と担当ごとに配置する運用を両立させたい。責任者とロールの両方に同じシフト操作権限を要求すると、設定が重複する。一方、責任者の業務上の呼び名と、そのシフトを一通り扱える性質は維持したい。

## 決定

- ロールは年度内の操作権限を持つ。「シフト作成」「全シフト管理」などを設定する。業務・UIでは「年度ロール」と呼ばない。
- シフトの責任者には複数のユーザー・ロールを指定できる。
- 責任者はそのシフトの全操作と連絡対応ができる。別のシフト編集権限を前提にしない。
- 全シフト管理の権限は担当外を含む全体を扱うために使う。
- 割当対象ロールは候補者の初期フィルタであり、責任者や操作権限とは別。
- ロールの操作権限は許可を合算する。メンバー・ロール管理の上下関係は最上位ロールで判定するが、責任者間の順位で担当シフトの操作は制限しない。

## 検討した選択肢

- 責任者を個人限定にする案：複数人や担当グループをまとめて指定する業務を表現できないため採用しない。
- 責任者指定と別途のシフト編集権限の両方を必須にする案：責任者が全操作できるという業務上の期待と合わず、重複設定になるため採用しない。
- 全体管理の権限だけで運用する案：担当ごとに管理範囲を分けられないため採用しない。

## 影響

- 認可では全体権限と対象シフトの責任者を区別して評価する必要がある。
- ロール所属の変更がシフトの操作権限・連絡先にも影響する。
- 有効化には実際に対応できる責任者が1人以上必要。削除・脱退等で不在になる場合は影響を警告し、続行時に無効化する。
- 連絡先の重複排除、権限変更時の接続・キャッシュ更新が必要になる。
- 希望閲覧の範囲、全体権限とチャット権限の厳密な関係、旧権限からの移行は別途設計する。
