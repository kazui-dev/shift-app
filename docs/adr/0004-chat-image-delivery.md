# 0004 チャット画像は原本を保存し、表示用は配信時に変換する

- 状態：採用
- 決定記録日：2026-09-13
- 実装状況：実装済み。詳細は[チャット画像の保存と配信](../design/chat-images.md)を参照。

## 背景

アップロード時に最大2400pxの静止WebPへ変換して保存し、一覧の小さなタイルでも同じ画像を展開していた。実機のスクロール計測で、2400pxの画像では画像が空になるフレームが出て、縮小画像では出なかった。また、保存した画像がWebPになり、元の画質・形式で残せなかった。

## 決定

- R2にはアップロードされた形式のまま、元の画素数の画像を保存する。HEIC・HEIF・AVIFだけJPEGに変換する。位置情報などのメタデータは除き、色の情報と写真の向きは残す。
- 表示用の画像（一覧用640・1280、画像詳細用2400、リンクカード用336）は、Images bindingで配信時に変換する。アップロード直後に一覧用を先に作る。
- 変換結果・保存用の原本・リンクプレビューはWorkers Cacheに置く。キャッシュを持つのは内部のentrypointだけで、公開側のentrypointが毎回ルーム閲覧権限と対象の存在を確認してから呼ぶ。ブラウザへは`private, no-store`で返す。
- ログイン中の利用者向けAPI応答と静的ファイルにはWorkers Cacheを使わない。
- 端末には一覧用の縮小画像とリンクカードの画像だけを残す。どちらもルームを開くたびに見るため。2400pxの画像と原本はメモリだけに置く。
- 公開URL・署名付きURLは発行しない。

## 検討した選択肢

- 2400pxのWebPだけを保存する案（従来）：一覧で大きな画像を展開して描画が遅れ、保存時に元の画質・形式を残せないため採用しない。
- アップロード時に全サイズを作ってR2に保存する案：保存量と削除処理が増え、サイズを変えるたびに作り直しが必要なため採用しない。
- 変換結果をCache APIに置く案：データセンターごとに分かれていて、アップロード直後に作った画像がほかの地域に届かず、削除時にも消せないため採用しない。
- 署名付きURLでCDNから直接配信する案（Discord方式）：URLが漏れると有効期限まで権限なしで見られ、閲覧権限を外れた利用者を次のリクエストから止める要件に反するため採用しない。
- JPEGまたはWebPに統一して保存する案：保存した画像が元の形式・画質にならないため採用しない。
- 送信済み画像を端末に一切残さない案（従来の要件）：ルームを開くたびとアプリの再起動のたびに一覧の画像を取り直すことになるため、一覧用の縮小画像とリンクカードの画像に限って条件付きで残す。
- API応答にもWorkers Cacheを使う案：毎回の認証とルーム権限の確認は省けず、短縮は小さい。一方で、編集や削除のあとに古い内容が見える危険があるため採用しない。

## 影響

- `docs/architecture.md`の「原本は保存しない」「送信済み画像はオフラインキャッシュへ保存しない」と、`docs/requirements.md`のオフライン対応を、実装時に書き換える。
- JPEG・PNG（APNGを含む）・WebP・GIF向けに、再圧縮せずメタデータだけを除く処理とテストが必要になる。
- Workers Cacheの内部entrypoint、キャッシュタグによる削除、`cross_version_cache`の設定が必要になる。変換の設定を変えるときは、キャッシュキーの版を上げる。
- Imagesの無料枠は月5000回の変換までで、1枚につき最大3回使う。
- R2の使用量は原本の分だけ増える。アップロードに合計サイズの上限を加える。
