# 0005 管理画面を共通メニューと通常ルートで構成する

- 状態：採用
- 決定記録日：2026-09-26
- 実装状況：実装済み。画面要件は[管理・シフト業務の設計](../design/management.md)を参照。

## 背景

管理トップから画面全体のダイアログを重ねる構成では、管理項目の切り替えとシフト一覧への復帰が別の操作になり、URL・戻る操作と画面の表示状態を合わせにくい。シフト作成と基本情報編集も一覧や編集表の中へ差し込まれていた。

## 決定

- `/manage` はシフト一覧へ進む。独立した管理トップは置かない。
- `/manage` の共通枠がヘッダーとメニューを保持し、各子ルートを右側の通常ページに表示する。スマホではメニューを開閉式にする。
- シフト一覧・作成・編集・基本情報と、ロール一覧・作成・個別編集は独立したルートにする。希望フォームや他の管理項目も右側の子ルートに置く。
- 管理年度は共通枠の左メニューでシフト・メンバー・ロールの上に常時置く。年度をまたぐ画面では表示内容の絞り込みに使わない。検索条件とスクロール位置は画面・年度ごとに保持する。
- 未保存の入力がある画面からの移動には破棄確認を出す。シフト移動では取得完了まで元の編集画面を残す。

## 影響

管理項目の直接URLとブラウザー履歴が画面表示に対応する。画面全体のダイアログと管理トップ用の経路は不要になる。API と DB の変更は伴わない。
