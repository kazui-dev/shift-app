# 0006 チャットの取得済み履歴と描画する行を分離する

- 状態: 採用
- 日付: 2026-10-01
- 実装状況: 実装済み。実データ・実機でのスワイプ性能はmainデプロイ後に利用者が確認する。

## 背景

取得済みページと送信待ちを全件DOMに置くと、会話パネルを維持した左右スワイプが
履歴件数の影響を受ける可能性がある。実機での原因確定はまだできていない。
Queryのページを捨てたり会話をアンマウントしたりすると、読み直しや復帰待ちが増える。

## 決定

`messageRows`の時系列配列を唯一の入力にする`useHistoryView`をチャット機能内に置く。
`@tanstack/react-virtual`で行IDをキーに測定し、可視範囲と前後2画面分をピクセルで選ぶ。
行数単位のoverscanにはしない。フォーカス中の行は例外として1行保持し、削除されたら
履歴のスクロール領域にフォーカスを戻す。DOM順と`aria-posinset` / `aria-setsize`を保つ。
日付・未読区切り・グループ間余白もメッセージ行の測定高さに含める。

仮想描画側がID・位置・高さの正となり、`MessageScroll`だけがスクロールを書き込む。
ライブラリのサイズ変化による自動補正とscrollToFn、ブラウザーのoverflow anchorは無効化する。
[公式チャット例](https://tanstack.com/virtual/latest/docs/framework/react/examples/chat)の
end anchoring / followOnAppendは、既存の未読開始・読書位置・近接下端・再訪の意図を
二重管理するため使わない。DOM全体の走査で位置を探す処理は除く。

先頭追加と実測サイズ変更は、表示中の先頭行のIDと画面内オフセットを維持する。
Reactのref測定直後も、座標を参照する前に保留中の測定を反映する。
ユーザーのscrollはcapture段階で記録し、その後の仮想範囲変更を位置復元と誤認しない。
ルーム再訪用に位置と実測値を最大20ルーム保持する。対象IDが削除された場合は保存した
sequence以降の最初の生存行、末尾を越えれば最後の行へ戻す。送信待ちは保存したindexを使う。
末尾を追っていたルームは新しい末尾へ戻す。

返信先は取得済みならDOMがなくてもIDから移動し、未取得なら既存Queryで過去ページを取得する。
遠い行の近傍への即時移動を挟まず、全距離をnative smooth scrollで移動する。
実測で目的地が変わると同じ座標系から移動先を更新し、同じ目的地への再発行を避ける。
対象がマウント・実測され、位置が2フレーム一致してからハイライトする。
タッチ・ポインター・ホイール・キー操作で取得待ちと移動を中断できる。motion reductionでは即時移動する。

メッセージ操作は履歴単位のイベント委譲で扱う。行は処理を登録するだけでdocumentリスナーを持たない。
長押しの移動・解放はdocumentで受け、行の外へ指が移っても取り消せる。
リンク・画像・返信ボタンの除外、右クリック、操作表示ボタンとEscapeは維持する。

画像は約2画面前から読み込む。IntersectionObserverの百分率marginは幅基準なので高さのpxへ変換する。
仮想行が外れると既存の`useHeldImage`のcleanupが参照を解放し、送信待ちのobject URLも参照数で解放する。
再表示は既存の画像プール、次いで端末のCache Storageを使用する。Queryページやoutboxは削除しない。
API、永続保存形式、Workerには変更がなく、一時互換は追加しない。

## 検証と残る確認

既存のスクロールテストに加え、実際のVirtualizerを使って先頭追加、遅延測定、削除、
sequenceによる復元、遠い返信先と中断、未読開始、短い大量行の描画範囲を検証する。
合成履歴のChromium検証は実機のフレーム落ち改善の証明とはしない。

大量の実データを読み込んだ同じ端末・ルーム・履歴範囲で、修正前後を比較する。
一覧パネルの処理が支配的かはまだ未確認なので、一覧の仮想化は計測後に判断する。
確認手順と未確認項目は[実行時の画面動作](../design/runtime-behavior.md#大量履歴の実機確認)に記す。
