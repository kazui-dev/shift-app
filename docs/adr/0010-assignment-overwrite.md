# 0010: 重複する個人の勤務を確認後に上書きする

2026-10-29 / Accepted

別シフトと重複する配置をエラーだけで止めず、キャンセルまたは上書き保存を選べるようにする。通常の保存APIで自動上書きすると旧画面から意図せず勤務が失われるため、確認・保存の専用APIを追加する。

新しい勤務の時間集合を既存の勤務から差し引く。9–12時へ10–11時を重ねる場合、既存は9–10時と11–12時として残る。勤務枠の時間自体を変更せず、割当を残余区間の枠へ移すことで同じ枠の他メンバーを維持する。空の元枠だけを削除扱いとし、必要人数と無関係な空枠は変更しない。

確認内容のtokenと全対象シフトの編集権限を保存時にも検証する。退勤のない現在の勤怠モデルでは勤怠記録の有無で上書きを制限しない。既存の勤怠と履歴は元の割当IDに保持し、新しいシフトには転記しない。全シフトの版・割当をbatch内で再確認し、競合は全変更をロールバックする。元の割当IDは最初の残余区間へ保持する。全体が置換される登録済み割当は取消済みとして監査可能な状態を残す。

個別編集と、その中の一括割り当ては別シフトとの重複を下書きに許容し、保存時に同じ確認画面と原子的保存を使う。同一シフト内の重複は従来どおり拒否する。全体一覧にも共通の確認画面と上書きAPIを接続する。複数シフトは従来の順次保存を維持し、各シフトの保存を原子的に行う。毎回最新状態に編集したメンバーの変更だけを反映し、前の上書きで変わった割当を古い下書きで復元しない。キャンセル時は未処理の保存を止め、未保存の下書きと取り消し履歴を保持する。
