# 0011 表示条件の永続保存とシフト吹き出しの共通化

- 状態：採用
- 決定記録日：2026-10-31
- 実装状況：実装済み

## 背景

管理画面の表示条件はReactのMapまたは画面内のstateだけに保持され、再読み込みで失われていた。個別シフトでは解除した希望回答・ロールが初期値で再選択され、年度内の別シフトにも条件が持ち越された。全体シフトだけPopoverへ移行したため、個別シフトのモーダルと必要人数の独自位置調整が残っていた。

## 決定

表示条件はlocalStorageへ保存する。共通の読み書き・検証・タブ間通知はWebのlib、利用者ごとのストアの生存期間はapp、項目と保存単位は機能が所有する。FilterMenuは保存先を知らず、値と変更通知を受け取る。

キーは版・利用者ID・画面・対象で分ける。シフト別一覧と全体表示は年度別、個別シフトと勤怠はシフト別、メンバー・ロール・希望提出状況は年度別、ユーザー一覧は利用者別、チャット一覧と新規宛先選択は年度別、チャット内検索と既存ルームの宛先選択はルーム別とする。検索、フィルターの値と含む／含まない、メンバーの並び順、シフトの表示モードを保存する。全体シフトの表示日も保持する。

未保存だけが初期値を使い、空配列・空文字・falseも明示的な選択として保持する。保存値はスキーマで検証し、壊れた値は初期値へ戻す。動的な候補は取得成功後の完全な候補一覧で整理し、取得中・失敗時やメニュー内検索で選択値を捨てない。保存不可でも現在のページ内では操作できる。

スクロール位置は従来の一時保持に分離し、スクロールごとにlocalStorageへ書かない。勤務の下書き・一括操作の選択・開いたパネル・区間に連動した候補表示・メニュー内の候補検索は永続保存しない。既存のカレンダーとチャットの訪問位置のsessionStorage、テーマ・管理年度・勤怠色分けのlocalStorageは維持する。

勤務編集と必要人数パネルは、共通のPopoverで位置調整・矢印・フォーカスを扱う。時間軸から開く吹き出しは、既存勤務・他シフトの勤務・空き時間のいずれも横位置をクリックした時刻、縦位置を勤務バーの上下端に揃える。勤務バーの描画と空き時間の位置計算は同じ寸法を使う。横位置は操作対象に対する比率で保持し、スクロール・幅の変化に追従する。名前からは名前を指し、キーボード操作では勤務バーまたは追加する開始時刻を使う。矢印は角丸に重ならない余白を確保する。

勤務編集は外側クリックで閉じ、そのクリックで他の勤務へ切り替えられる。入力フォームだけを対象変更時に初期化し、吹き出しの土台を作り直さない。Escape・取消では操作元へ戻り、外側の操作ではフォーカスを奪わない。必要人数パネルは候補者の操作中も維持し、時間軸の上側へ表示する。全体のシフト選択と個別の複数勤務編集は機能側に残す。

矢印の描画は[Base UIの公式例](https://base-ui.com/react/components/popover)に沿い、Popupを配置基準とし、回転した内側の四角をクリップして三角形にする。矢印は高さ14px・幅20pxとし、Positionerの距離を矢印の高さ・対象との隙間4px・本体の境界線から計算する。角丸からの余白はarrowPaddingで確保する。

勤務のクリック範囲は全体・個別・他シフトで行の高さ全体に広げ、表示する帯の高さとは分離する。勤務がある時間帯は上下の余白も編集対象とし、空き時間だけ追加できる。吹き出しの縦位置は表示する帯を基準に保つ。勤務上のドラッグは両端のハンドルでのみ開始し、空き時間のドラッグによる追加は維持する。

勤務フォームの操作文言は「キャンセル」「反映」に揃える。表示開始時のシフト・開始・終了と入力が同じ間は両ボタンを無効にし、変更後も元の値へ戻せば再び無効にする。×・外側クリック・Escapeで閉じる操作は変更の有無に依存しない。

## 影響

再読み込み後も全解除を含む条件が復元される。同じ端末の別利用者や別シフトの条件が混ざらない。端末間の同期は行わない。表示条件の保存はAPI・DB・認可を変更しない。旧Webは新しい版付きキーを参照しないため、そのまま戻せる。

## 勤務のシフト変更

個別シフトの他シフトの勤務帯も、その勤務を対象に同じ吹き出しを開く。現在のシフトへの新規追加として扱わない。既存勤務は人・時間を保持してシフトを変更できる。2026-11-01に、実績の訂正を妨げないため、終了済み・勤怠記録や履歴がある勤務の移動制限を警告表示へ変更した。追加の確認操作は求めず、元の勤怠記録・履歴は元の割当に保持し、移動先へ転記しない。

移動元と移動先の変更は同じ下書き履歴に入れ、一回の取り消しで両方を戻す。保存は `PUT /api/activities/plans` にまとめ、対象すべての編集権限・版・勤務範囲を検証する。全対象の旧割当を除いてから新割当を作ることで、送信順に左右されず移動を保存できる。終了時刻と勤怠は書き込みトランザクション内でも再検証する。失敗時は全体をロールバックし、画面の下書きを残す。第三の勤務との重複はこの保存では拒否し、自動上書きしない。既存の単一シフト保存・上書き操作は維持する。
