# 0012 一覧の表処理をTanStack Tableへ集約する

状態: 採用

## 背景

シフト別一覧はCSS Grid、メンバー一覧はHTML tableで、列・並べ替え・絞り込み・選択を個別に管理していた。列名の横へ検索・フィルターをまとめる際に、表示と状態管理の重複も整理する。

## 決定

- TanStack Table v9を採用し、シフト別・メンバー・ユーザー・ロール・年度の一覧を移行する。既存のBase UIとデザイントークンを使うため、完成済みグリッドの外観を導入しない。
- `packages/ui` は表の描画、列見出し、入力フィルター、絞り込み・並べ替え・行選択の基盤を所有する。列の意味、候補データ、API、保存キー、編集操作は各機能が所有する。
- 列定義の参照を安定させ、検索・フィルターの条件を列定義と分けて共通の見出しへ渡す。入力や候補選択でメニューを再mountしない。
- 表示条件は既存の `useViewPreference` の値を制御状態として渡す。Table側に永続保存を追加しない。空選択、除外、未設定、列内OR・列間ANDを維持する。
- 行の識別にはレコードIDを使う。絞り込みで隠れた行の選択を保持し、全選択・解除は表示行を対象にする。
- 5一覧は同じ `DataTable` で見出しの固定、罫線、セルの余白・文字、狭幅表示への切り替えを管理する。コンテナ幅448px未満だけ縦並びにし、列名とフィルターは残す。個別の横スクロールや一覧上部の余白・罫線を追加しない。上下左右の余白とスクロールバーの非表示は共通の `ScrollViewport` で扱う。スクロール要素自身に余白を付けず、内側の本文に付ける。見出しは初期位置からスクロールに追従して上がり、スクロール領域の上端で固定する。一覧と時間軸は同じ `sticky-header` を使い、下の区切り線を見出し自身が保持する。見出しの上線は付けず、ページヘッダーの下線と二重にしない。

## 範囲と結果

各列の条件はその列の見出しから操作する。列の見出しは未選択なら項目名、1件なら選択値、複数なら項目名と件数を表示する。入力条件は入力値を表示し、解除すると元の項目名に戻す。ラベルの規則は通常のフィルターボタンと共有する。アイコンの幅と間隔を除いた残り幅でラベルを省略し、アイコンを次の行へ落とさない。シフト一覧の日時は `10/7(土) 09:00-18:00` の形式で、日付と時刻の間に強制改行を入れない。シフト名、メンバー名、ユーザー名、ロール名、学籍番号は入力による部分一致、担当・場所・ロール・タグ・参加年度は候補を検索して選択する。固定候補の状態・管理権限・システム権限には入力欄を設けない。「含む／含まない」は選択を独立して保持し、同時指定できる。切り替えは編集する側を変更するだけで、同じ値を反対側で選び直すと移動する。カラム名の件数は両側の合計、ツールチップと印刷は両条件を表示する。シフトの行全体から詳細へ進める操作を維持する。メンバーの並べ替え、表示外の選択、一括変更、失敗した対象の再試行も維持する。

ロール作成・並び順の保存・年度作成の入口も共通ページヘッダーに置く。メンバー画面の「ロールを管理」「タグを管理」は廃止し、ロール・タグは管理メニューから開く。タグ一覧も共通テーブルと並べ替えを使い、作成・名前変更・削除を提供する。ロール・タグの行から所属メンバー一覧へ進み、名前・学籍番号・ロール・タグの共通列とフィルターで確認する。メンバー追加は未付与者を同じテーブルで選択し、解除は所属一覧の選択行にだけ適用する。設定は各対象の設定ページで編集する。シフト一覧は表示モード「シフト別／全体」をヘッダーに置くため、PCでは「シフト」のタイトルを重複表示しない。それ以外の管理画面はページタイトルを表示する。サイドバーが隠れるモバイルと、個別シフトなど対象を示す見出しも維持する。メンバーとユーザーは同じ選択列・行クリック・選択件数・解除ボタンを使い、選択した場合だけページヘッダー左側に一括操作を表示する。ユーザーの個別詳細パネルを廃止し、年度と権限を複数人に変更できる専用フォームへ置き換える。年度は参加・解除の差分だけ適用し、権限変更は理由を必須にして本人を除外する。成功した対象は再送せず、失敗した項目だけを再試行する。名前のホバー下線をアイコンへ適用しない。ロール・タグの各行には常に6点のドラッグハンドルを表示し、dnd-kitでポインター・タッチ・キーボード操作を共有する。変更は下書きに保持し、「並び順を保存」で年度共通の順序へ反映、「キャンセル」で破棄する。両ボタンは未保存の変更がある場合だけヘッダー左側に「並び順を保存」「キャンセル」の順で表示する。ロールの順序は権限の上下関係にも使うため、編集可能な範囲だけを動かす。タグの順序は表示専用で、権限には影響しない。下書き・保存・キャンセル・保存前の順序変更検出は共通の処理を使う。絞り込みは維持し、非表示行の位置は動かさない。メンバー画面から年度への追加・解除・前年度からの引き継ぎを廃止し、参加年度の変更はシステム管理者のユーザー画面に集約する。

表示モードはシフトページのヘッダー左側、シフト希望フォーム・作成は右側に置く。全体表示の日付・条件・印刷・元に戻す・保存は本文のツールバーに置く。各シフト内と全体で `ShiftWorkspaceToolbar` と `ScrollViewport` を共有し、操作欄がスクロールした後、時間軸だけを上端で固定する。全体表示の保存ボタンはヘッダーへ転送しない。各シフト内の保存位置は従来のヘッダーを維持する。単なる勤務メニューの表示を未保存変更として扱わず、反映済みの下書きと保存中を移動制御に使う。保存中は表示切り替えとページ移動を止める。ページ移動の確認は `NavigationGuard` で共通化し、保存中に押しても進めない確認ボタンは出さない。入力内容とdirty/pendingは各機能に残し、ページの移動制御はフォームの外に置く。ページからモーダルへ変更する場合も、フォームの状態を移動制御へ依存させない。

取得失敗時のメッセージと再読み込みボタンは共通部品で表示する。操作履歴は履歴リスト、シフト希望フォームは設定・提出状況という役割を保ち、表の列定義へ無理に合わせない。いずれも共通ページ枠とスクロール領域を利用する。

5一覧・全体は各シフト内と同じく利用可能な横幅を使い、共通の上下左右の余白（狭幅16px、sm以上24px）を持つ。中央寄せの最大幅を作業画面に適用しない。`ManagementViewport` が本文の縦スクロールを所有し、一覧と全体の位置を別々にページ内で記憶する。ツールバーに時間軸と重複する罫線を置かない。

PCの管理サイドバーは全画面で常時表示し、幅を160pxに揃える。内側の左右余白は従来の12pxを維持する。個別シフトだけを折りたたむルート判定・開閉操作・開閉状態は廃止する。モバイルは従来のメニューを使う。表示年度の切り替えUIは一時的に外し、選択・保存・復元の処理は互換として維持する。「管理」と年度を常時表示する共通ヘッダーは廃止する。モバイルの管理メニュー入口は各ページのヘッダーに組み込み、別のヘッダー行を増やさない。各シフト内と作成画面の機能・責務の再設計は別PRに残す。

時間軸は `ShiftTimeline` と勤務編集の部品を維持する。Tableを導入しても時間軸のスクロール性能改善にはならず、仮想化は実測と操作要件を踏まえて別途判断する。
