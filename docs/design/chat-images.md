# チャット画像の保存と配信

- 状態：合意済み。実装済み。
- 実装状況：Workers Cacheの基盤（`SharedCache` entrypoint）、リンクプレビュー、リンクカードの画像、アイコン、チャット画像の保存・配信・表示を実装済み。
- 判断の理由：[ADR 0004](../adr/0004-chat-image-delivery.md)
- 現行の実装：[アーキテクチャ：チャット画面と画像](../architecture.md#チャット画面と画像)

## 画像の種類と使い道

| 画像               | 内容                                                                                                               | 置き場所                          | 使う場所                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ | --------------------------------- | ---------------------------------------------------------------------------------------- |
| 保存用の画像       | アップロードされた形式・元の画素数                                                                                 | R2。返すときはWorkers Cacheを通す | 保存ボタン                                                                               |
| 一覧用の縮小画像   | 長辺640または1280のWebP（品質85）                                                                                  | Imagesで変換してWorkers Cache     | メッセージ一覧のタイル、画像詳細の下のサムネイル（640）                                  |
| 画像詳細用の画像   | 長辺2400のWebP（品質85）。小さい画像は拡大しない                                                                   | Imagesで変換してWorkers Cache     | 画像詳細の大きな表示                                                                     |
| 表示用のコピー     | 長辺2400のWebP（品質90）。画像を選んだときに端末で作る。元より3割以上小さくならない画像とGIFは作らず元の画像を使う | 端末。元の画像より先にR2へ送る    | サイズの読み取り、送信直後のタイル。R2では元の画像が届くまで一覧用・画像詳細用の元になる |
| リンクカードの画像 | 336×336の正方形に切り抜いたWebP                                                                                    | Imagesで変換してWorkers Cache     | リンクのカード                                                                           |
| アイコン           | Discordの128pxのWebP                                                                                               | DiscordのCDN                      | アイコン全般                                                                             |

一覧用の縮小画像のサイズは、次のように使い分ける。

| タイル                                                           | サイズ |
| ---------------------------------------------------------------- | ------ |
| 1行に2枚、1行に3枚、3枚のときの右の2枚、画像詳細の下のサムネイル | 640    |
| 1枚だけ、1行に1枚、3枚のときの左の1枚                            | 1280   |

## アップロード

| 項目           | 決定                                                                                                                                                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 受け付ける形式 | JPEG、PNG、WebP、HEIC・HEIF、AVIF、GIF、アニメーションWebP、APNG。SVG・BMP・TIFFは受け付けない                                                                                                                                                                                       |
| 保存形式       | JPEG・PNG・WebP・GIF・APNGはそのまま。HEIC・HEIF・AVIFはJPEG（品質92）に変換する。変換で一辺が12000pxを超える場合は、長辺12000pxに縮小する                                                                                                                                           |
| メタデータ     | EXIF（向き以外）、XMP、コメントなどを除く。色の情報（ICCプロファイル）とEXIFの向きは残す。HEIC・HEIF・AVIF以外は再圧縮しない                                                                                                                                                         |
| アニメーション | 保存用はアニメーションのまま。表示用は1コマ目の静止画                                                                                                                                                                                                                                |
| 上限           | 1枚20MB、5000万画素、1投稿10枚。利用者・ルームごと・24時間で、一般は100枚かつ1GB、リーダーとルーム管理者は300枚かつ3GB、システム管理者は1000枚かつ5GB（高いほうを使う）。アップロード開始時に数え、送信前に外した画像の分は戻す                                                      |
| ファイル名     | アップロード時の名前を添付の記録に保存し、保存名に使う。`/ \ : * ? " < > \|` と制御文字は取り除き、255バイトまでにする。空または拡張子だけになった場合は送信日時（日本時間、秒まで）を使う。JPEGに変換した場合は拡張子を`.jpg`にする。同じ名前が重なっても変えない。画面には出さない |
| 送る順番       | 表示用のコピーを作れた画像は、コピーを先に送ってメッセージを投稿する。元の画像は投稿のあと、ほかのアップロードと送信待ちがないときに1枚ずつ送り、届いたらR2の画像を置き換えて一覧用・画像詳細用を作り直す。届くまでは保存ボタンを出さない                                            |
| 元の画像の再送 | 元の画像は届くまで端末に残し、アプリを開くたびに続きから送る。期限はない。画像が消えたなど受け付けられないときは送るのをやめる。ログアウトの前には、送っていない元の画像についてコピーを元の画像として扱うよう伝える                                                                 |
| 先回りの変換   | アップロード直後に640と1280を作ってWorkers Cacheに入れる                                                                                                                                                                                                                             |
| 保存期間       | メッセージまたはルームを削除するまで残す                                                                                                                                                                                                                                             |

## サーバーでの配信

- 公開側のentrypointは、Workers Cacheを使わない。毎回、ログイン、ルームの閲覧権限、添付またはメッセージの存在を確認する。
- 確認が通った場合だけ、キャッシュを持つ内部entrypointを`ctx.exports`で呼ぶ。内部entrypointのキャッシュキーは`/v1/添付ID/サイズ`のように、利用者に依存しない値にする。
- 内部entrypointは`public`で返し、公開側が`private, no-store`、`nosniff`、same-origin resource policyに付け替えてブラウザへ返す。
- 期限は、変換結果と保存用の画像が30日、リンクカードの画像が7日、リンクプレビューの内容が24時間（取得に失敗した場合は5分）。
- 添付ごと・ルームごとのキャッシュタグを付け、メッセージ削除やルーム削除のときに消す。
- `cross_version_cache`を有効にする。変換の設定を変えるときは、キャッシュキーの版（`v1`）を上げる。
- リンクカードの画像は、外部の画像を20MBまで取得し、Imagesで縮小する。現行のCache API（`chat-link-previews`、`chat-link-images`）はやめる。
- ログイン中の利用者向けAPI応答と静的ファイルには、Workers Cacheを使わない。

## 端末での保持

| 画像                     | 保持                                                                                                                                                                                                        |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 一覧用の縮小画像         | 端末のキャッシュに残す。最後の表示から14日、100MBまで。枚数の上限はない。閲覧権限を外れたルームの分、ログアウト時、別の利用者を確認した時に消す。オフラインでは、最後のオンライン確認から24時間まで表示する |
| リンクカードの画像       | 一覧用の縮小画像と同じ枠と条件で端末のキャッシュに残し、メモリでも同じ64MBの中で保持する。メッセージを削除した時にも消す                                                                                    |
| 画像詳細用の画像         | メモリだけ。10枚まで                                                                                                                                                                                        |
| 保存用の画像             | メモリだけ。画像詳細で表示中の画像と、その前後の画像の分。画像詳細を閉じたら手放す                                                                                                                          |
| 一覧用の縮小画像のメモリ | 64MBまで。ほかの種類とは分けて数える                                                                                                                                                                        |
| 下書き・送信待ちの画像   | 元のファイルを利用者・ルーム別のIndexedDBにコピーする。コピーできなくても表示は変えずに添付を続け、実際に読めなくなった時だけ「画像を読み込めませんでした。もう一度添付してください」と知らせる             |

## 表示

| 場面                   | 挙動                                                                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ルーム一覧を見ている間 | 上から5ルームについて、開いた時に見える範囲とその上1画面分の画像とリンクカードの画像を先に読み込む                                                          |
| ルームの中             | スクロールの先2画面分の画像とリンクカードを先に読み込む。表示済みの画像は、メッセージが履歴から外れるまで保持する                                           |
| 送信中                 | 端末のプレビューを表示する。端末でHEICを読めない場合は、画像アイコンの枠を表示する                                                                          |
| 送信直後               | 端末のプレビューを表示し続け、サーバーの縮小画像の展開が終わってから差し替える                                                                              |
| 画像詳細を開いた時     | 手元の一覧用の縮小画像のうち、大きいほうを先に出す。2400pxの画像の展開が終わったら差し替える。同時に、表示中の画像と前後の画像の保存用を裏で読み込む        |
| 保存ボタン             | スマホは共有画面（Web Share API）、PCはダウンロード。共有画面を出せなかった場合はダウンロードにする。保存用の画像を取得できなかった場合はトーストで知らせる |

## デプロイ後に確認すること

- ローカル開発でWorkers Cacheが動くか。
- 公開側のentrypointでキャッシュを無効にした時、静的ファイルの配信に料金がかかるか。
- アカウントのプランと、Imagesの無料枠（月5000回）に収まるか。
- EXIFの向きだけを残したJPEGが、Android・iPhoneの写真アプリとWindowsで正しい向きに表示されるか。
- iPhoneのPWAで、先に読み込んだ画像を共有画面に渡せるか。
- Imagesのアニメーションの上限（全コマ合計5000万画素）が、1コマ目だけを出力する場合にも適用されるか。

## 今後の展望

- 動画の添付。Cloudflare Streamは有料契約と、再生リストを中継できない制約のため使わない。R2に元の動画を置き、画像と同じくWorkerが毎回権限を確認して配信する形が候補。iPhoneのHEVC動画を再生できない端末の扱い、大きさ・長さの上限、サムネイル、再生の見せ方を決める必要がある。
