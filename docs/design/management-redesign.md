# 管理・シフト作成の刷新設計

## この文書の位置づけ

状態：管理・年度・シフト希望・シフト編集・チャット・出勤の刷新を実装。実装上の境界と保留事項は末尾に記載する。

管理・シフト作成・年度・チャットの刷新について、合意済みの要件、仮置きのUI、未決事項をまとめる。設計の進展に合わせて更新し、過去の版はGitで追う。仮置き・未決の項目は本文と末尾で明示する。

API・UI・画面構成を現行構造に縛られず刷新し、不要な旧実装・互換用の別経路を残さない。既存データを消すという意味ではない。移行はD1マイグレーション0012〜0025で行う。

本書は変更後の設計を扱い、現行実装の説明を置き換えない。実装時に、要件・アーキテクチャ・データベース等の関連文書へ反映し、実装状況を更新する。

重要な判断の背景・影響は [ADR一覧](../adr/README.md) から参照できる。
文書全体の役割と更新方法は [ドキュメント案内](../README.md) を参照。

## 用語とデータの基本方針

| 用語           | 意味                                                                             |
| -------------- | -------------------------------------------------------------------------------- |
| ユーザー       | 年度をまたぐアプリ利用者                                                         |
| メンバー       | ある年度に参加しているユーザー                                                   |
| ロール         | 年度内で管理する、人のまとまりと操作権限。業務・画面では「年度ロール」と呼ばない |
| 責任者         | 指定されたシフトの全操作と連絡対応を担うユーザー・ロール                         |
| シフト         | 仕事内容・日時・場所などを持つ業務のまとまり                                     |
| 時間枠         | シフト内の勤務時間の区切り                                                       |
| 割当           | メンバーを時間枠に紐付けること                                                   |
| デフォルト年度 | システム管理者が決める、表示年度の初期値・追従先                                 |

- 年度をまたぐ利用者は `app_users` に統一した。
- 年度への参加は `year_memberships` で表す。認証用の `user` とアプリ利用者は区別する。
- 関連する列名・API・型名までどう統一するかは実装時に整理する。
- 「割当」は内部設計の用語とし、UIには使わない。本書の「配置画面」等も説明用の呼称であり、画面上の最終文言は別途決める。
- 局・担当の固定階層は導入しない。業務上のまとまりはロールで扱う。
- 勤務時間は時間枠が持つ。同じ枠に属する人だけ別の勤務時間を持つ構造は採用しない。
- 代役専用のデータは設けない。交代は割当変更とその履歴で扱う。

## 画面構成とデザイン

各項目は専用ルートを持つ。管理は `/manage/shifts`・`/manage/members`・`/manage/roles`、システム管理は `/manage/users`・`/manage/years`・`/manage/discord-link-requests`・`/manage/audit` に置く。

| グループ     | 項目            | 主な責務                                           |
| ------------ | --------------- | -------------------------------------------------- |
| 管理         | シフト          | 選択年度のシフト業務への入口                       |
| 管理         | メンバー        | 選択年度の参加者・ロール付与                       |
| 管理         | ロール          | 選択年度のロール・権限・上下関係                   |
| システム管理 | ユーザー        | 全ユーザーの参加年度・システム権限・アカウント確認 |
| システム管理 | 年度            | 年度作成・デフォルト年度の切り替え                 |
| システム管理 | Discord連携申請 | 当面は現行機能を維持                               |
| システム管理 | 操作履歴        | 当面は現行機能を維持                               |

- 「管理」はグループ名・ナビゲーション項目名として使う。左上にページタイトルとしてわざわざ重ねて表示しない。
- シフト配下は「シフト一覧」「シフト希望フォーム」を採用する方向。
- 独立した管理メニューの「遅刻欠勤連絡」は廃止し、チャットとシフト詳細に統合する。
- デザイン・操作感は既存カレンダーを基準にする。文字組み、余白、情報密度、時間の表現、選択・編集の挙動を揃える。
- シフト管理はPCでの作業を主軸にするが、スマホでも必要な操作に対応する。
- 情報や操作を常時並べすぎない。人・希望・割当を中心にし、詳細や操作は必要なときに開く。
- 作成済みの配置画面ラフは設計確認用であり、デザインの完成案ではない。情報量が多すぎるという指摘を反映する。

## 年度と表示年度

### デフォルト年度

- 年度の「準備中・運用中・終了」の3状態は廃止する。
- 初期設定後はデフォルト年度が必ず1個存在することをDBで保証する。単に「最大1個」ではない。
- 別年度をデフォルトにしたら一括で切り替える。全年度をOFFにする通常操作は設けない。
- デフォルト年度は表示の初期値・追従先であり、他年度を管理・閲覧できなくするものではない。
- システム管理の年度一覧ではデフォルトが一目で分かり、他年度に「デフォルトにする」を置く。同じ画面で年度を作成する。
- 年度一覧での具体的なON/OFFデータ表現は未定。画面上のシフトの有効・無効と混同しない。

### カレンダー・希望回答・チャット

- この3画面で表示年度を共有する。
- 切り替えは設定の「表示年度」で行う。各画面に年度セレクトを常設しない。
- 選択肢は「2026年度」「2027年度」のような年度だけ。「自動」「デフォルト年度を使う」という項目は置かない。
- アクセスできる年度だけ選択できる。過年度の利用も権限があれば認める。
- 初期表示は、デフォルト年度に参加していればその年度、未参加なら参加年度のうち最新とする。参加年度がなければ未参加の案内を出す。
- 本人が切り替えていなければ、デフォルト年度の変更に追従する。新しいデフォルト年度に未参加なら、参加年度のうち最新にフォールバックする。
- 本人が別年度を選んだ場合は、その選択を保持する。
- 表示年度はユーザーごとに保存し、端末間で共有する。
- 選択年度へのアクセスを失った場合は、アクセス可能なデフォルト年度、なければアクセス可能な最新年度へ切り替え、その旨を知らせる。
- 現在のデフォルト年度を選び直したら、以後の年度変更への追従に戻る。UIには内部の追従状態を選択肢として出さない。
- デフォルト以外を見ている間は、現在の年度を各画面で控えめに示す方針。

### 管理

- 管理のシフト・メンバー・ロールで選択年度を共有する。
- 管理側の共通ヘッダーに年度セレクトを置く。選べるのは本人が管理できる年度だけ。
- 選択肢が1年度しかなければ、年度名だけ表示する。
- カレンダー等の表示年度とは別に保持する。管理で来年度を準備しても、本人のカレンダー・チャットは切り替わらない。
- 管理側の選択は端末ごとに保持する。管理可能な保存済み年度を優先し、なければ管理可能なデフォルト年度、次に最新年度を選ぶ。
- 管理権限を失った選択年度も同じ優先順で切り替え、その旨を知らせる。

## メンバー・ユーザー管理

### 年度への参加

- 初回のユーザー登録完了時にデフォルト年度へ自動参加する。管理権限を持つロールは自動付与しない。
- デフォルト年度を切り替えただけでは、既存ユーザー全員を新年度へ参加させない。
- 新年度には前年度のメンバーを選んで一括追加できる。
- 引き継ぎの標準は年度参加だけ。必要ならロールと付与先も選んでコピーできる。
- 参加解除でも過去の実績・連絡・履歴を保持し、その年度の利用権限を外す。
- 今後の割当が残る場合は一覧を示し、割当変更・取消を済ませてから参加解除する。

### メンバー画面

- 選択年度の参加者を学籍番号順に並べ、名前・学籍番号・付与ロールを確認できる。
- 名前・学籍番号で検索し、ロールで絞り込める。
- 主な作業はロールの付与・変更。
- 一覧のロール欄から、その場で選択欄を開いて付け外しできる。
- 複数人を選んでロールを一括追加・解除できる。追加で他の既存ロールを置き換えない。
- 一括操作欄はメンバーを選択したときだけ表示する。
- 選択中の変更をまとめ、「適用」で反映する。一括操作でも対象人数・追加解除の内容が分かる。
- 「メンバーを追加」から年度未参加ユーザーを検索・複数選択して追加する方向。
- 「前年度から選ぶ」も同じ入口で扱い、コピー設定などはその方法を選んだときだけ表示する。詳細UIは仮置き。

### ユーザー画面

- システム管理者が、年度未参加者も含む全ユーザーを学籍番号順に確認する。
- 一覧は名前・参加年度・システム権限を基本とする。
- 一人を開いて、年度参加・システム権限を変更し、アカウント情報・Discord連携状態を確認する。
- 年度参加はメンバー画面と同じデータを別の入口から扱う。日常的なロール編集はメンバー画面に集める。

## ロール・権限・責任者

### ロールの権限

- メンバー管理、ロール管理の操作権限を分ける。
- シフトについては「シフト作成」「全シフト管理」のように、年度全体で可能な操作を設定する。
- 複数ロールの操作権限は許可を合算する。
- ロールの並び順を権限上の上下関係にも使う。表示順だけという案は採用しない。
- 上位ロールが下位ロールの操作権限を自動継承することはない。
- 上下関係の判定には本人の最上位ロールを使う。
- 付与・編集できるのは自分の最上位ロールより下。同格・上位のユーザーのロールは変更できない。
- 自分以上の位置への並べ替えは禁止する。自分が持たない権限の付与も禁止する。
- システム管理者は全年度を管理できる。
- チャットの閲覧・投稿・設定変更はルーム単位で設定し、この権限とは範囲を分ける。

### 責任者

- シフトごとに複数のユーザー・ロールを混在して指定できる。
- 責任者は指定シフトの全操作と連絡対応ができる。別途シフト編集権限を持つことを必須にしない。
- 全シフト管理権限を持つ人は担当外を含めて管理できる。
- ロールを責任者に指定するのは、人のまとまりを指定するため。個人複数人の直接指定も可能で、シフトごとにロールを作る必要はない。
- 責任者間のロール順位で担当シフトの作業を制限しない。
- 割当対象ロールは責任者とは別設定。
- 複数の指定経路で同じ人が含まれても、同じ通知を重複して送らない。

### 有効化と責任者不在

- 作成時から責任者を設定できる。初期値は作成者本人。
- 責任者が空でも作成・保存できるが、有効化には実際に対応できる人が1人以上必要。
- 所属者0人のロールだけでは有効化の条件を満たさない。
- 有効なシフトから最後の責任者を直接外す場合は、別の責任者を指定するか、無効にして保存する。
- ロール削除・ロールからの脱退・年度参加解除などで最後の責任者がいなくなる場合は、対象シフトを警告し、続行すると無効にする。

### ロール画面・削除

- PCは左にロール一覧、右に名前・色・権限の編集。スマホは一覧から詳細へ進む。
- 所属メンバーも確認できる。モダンで、既存カレンダーと統一したUIにする。
- 使用中のロールも、使用先と影響を警告して確認すれば削除できる。事前の付け替えは必須にしない。
- 削除時はメンバーへの付与と各設定から対象ロールを外す。
- 責任者不在になるシフトは上記の規則に従って無効にする。
- 割当対象ロールの削除で、候補者が意図せず全員に広がらないようにする。未指定時の全員表示と区別する具体方式は未定。

## シフト業務と基本設定

### 業務の進め方

- 希望を集めて管理側が配置することが基本。全体で配置する場合と担当の責任者が配置する場合の両方に対応する。
- 希望受付・シフト作成・割当は並行できる。受付終了を割当開始の条件にしない。
- 「下書きから公開へ」という必須段階は設けない。シフトの状態は有効・無効。
- 有効なら通常画面への表示・通知の対象となる。無効でもシフト・枠・割当を保持する。
- 有効・無効で配置上の扱いは変えない。無効シフトの割当も重複判定と割当時間の合計に通常どおり含め、合計を有効・無効で分けない。
- 作成時の初期値は無効。条件を満たせば作成時に有効にできる。
- 責任者がいれば、時間枠・割当がまだなくても有効化できる。

### 割当・変更・複製・削除

- 同じ人への時間が重なる割当は、担当やシフトをまたいでも保存不可。競合する割当を示す。
- 希望外・希望未提出の人への割当は、警告を確認すれば保存できる。
- 人数は任意の目安。未設定でも使え、割当を制限しない。
- 割当対象ロールは候補者の初期フィルタ。制約ではなく、解除して対象外の人も割り当てられる。
- 最初から割当対象ロールが未指定なら、年度内の全メンバーを候補とする。
- 割当対象ロールの変更で既存の割当を変更しない。
- シフトの日程変更で割当が範囲外になる場合は、対象者を示し、枠・割当を整合させてから保存する。勤務時間を勝手に移動しない。
- 交代は管理者・責任者による割当変更で扱う。本人同士の交代申請・承認機能は不要。
- 誰が、いつ、誰の割当を変更したかを履歴に残す。元の欠勤連絡は元の割当に残し、交代した人へ移さない。
- 複製では基本情報・責任者・割当対象ロール・時間枠を引き継ぎ、日付を指定できる。割当は標準では引き継がず、複製先は無効とする。割当を任意でコピーするUIの有無は未確定。
- シフト削除時は枠・割当・チャット・遅刻欠勤連絡も削除し、削除操作の履歴は残す。失われる内容を警告してから実行する。内容を残したい場合は無効化する。

## 時間枠と配置画面

### 時間枠のルール

- 割当は必ず時間枠に所属する。枠だけ先に作れるほか、割当操作の中で枠を作れる。
- 人を見る前に枠を決める手順は必須ではない。参加できる人を見て枠を決める流れも支える。
- 定型枠への配置が基本になりうるが、等間隔で自動生成する案は採用していない。
- 同じ枠のメンバーの勤務時間は共通。違う時間なら別枠で管理する。
- 枠同士の時間の重なりは許可。同じ人の割当重複は不可。
- 枠の時間変更は所属メンバー全員に反映する。他の割当との重複は保存不可、希望外は警告。
- 一人を別枠へ移す操作を用意する。移動先の枠もその場で作れ、元の割当を先に削除する必要はない。
- 空になった枠は自動削除しない。必要なら明示的に削除する。
- 複数枠へ同じ人を一括配置する操作は現時点では設けない。

### 一覧と遷移

- シフト一覧は1件を1行として扱うことを基本にし、責任者ロールで重複する分類一覧を作らない。
- 初期表示は有効・無効の両方。状態やロール等で絞り込める。
- 初期ソートは開始日時順。更新が新しい順・シフト名順にも切り替えられる。
- 同じ開始日時のタイブレークは終了日時・名前の順とする案。
- PCでは一覧を左、詳細を右に表示する方向。スマホでは一覧から詳細へ遷移する。
- 各シフトの詳細から専用の配置画面へ進み、画面を広く使う。導線のUI文言に「割当」は使わない。
- 配置画面は選択シフトの日付・時間範囲に固定。日付切り替えは置かない。

### 人と時間を見渡すことを中心にする

- 縦にメンバー、横に時間を並べる。人数の増加には縦スクロールで対応する。
- ロールの絞り込みはメンバー列の補助フィルタとする。シフトに候補ロールを設定した場合は初期表示に反映する。
- メンバーは学籍番号順。配置操作で行が勝手に移動しない。
- 提出された参加可能時間、他シフトの割当、作業中シフトの割当を同じ時間軸で見られる。
- 希望未提出と不参加を区別する。一部だけ参加可能な人は必要時に確認できればよい。
- 時間帯を指定すると、参加可能かつ他の割当と重ならない人を強調できる。該当者だけへの絞り込みも可能とする案で仮置き。
- 人を見て時間を考える場合と、時間から人を探す場合の両方に対応する。
- メンバーごとの当日の全シフトの割当時間を補助表示し、年度全体の合計も確認できる。
- 合計は未保存の変更を含めて即時更新する。負担の目安であって制限ではない。
- 枠一覧を常設しない。クリック・ドラッグでシフトを作成し、メンバー行に対応する非モーダルのサイドパネルで希望時間と複数のシフトを編集する。1分単位で入力でき、ドラッグは5分刻みとする。
- 学籍番号・合計・詳細フィルタなどは、ソートや判断に使えても常時大きく表示する必要はない。

### 保存と編集履歴

- 配置変更は画面内でまとめ、「保存」で反映する。編集中の内容は本人向け画面へ逐次反映しない。
- 保存後も配置画面を開いたまま作業できる。保存は編集セッションの終了ではない。
- 元に戻す・やり直すを用意する。枠の作成・変更・割当・移動・削除が対象。
- 保存しても操作履歴をリセットしない。保存済み操作を戻した結果は、新しい未保存変更となり、再保存で反映する。
- 同じ配置画面で作業している間は履歴を保持する。再読み込み・再入場をまたぐ保持は未確定。
- ショートカットは `Ctrl / Cmd + Z`、`Ctrl / Cmd + Shift + Z`。入力欄では文字入力の取り消しを優先する。
- 一括操作はひとまとまりで戻す。
- 同時編集で先に保存された変更を上書きしない。後から保存する側に競合を知らせ、手元の編集内容も保持する。
- 他の管理者の操作を取り消してしまわないよう、履歴と競合の整合方法を別途設計する。
- 未保存で離れる場合は「変更を破棄して移動しますか？」に「キャンセル」「破棄して移動」の2択。「保存して移動」は設けない。

### 通知

- 保存結果は画面に反映するが、割当・変更の通知は管理側が未通知の変更をまとめて送る。
- 保存・通知・シフトの有効無効はそれぞれ別の操作。
- 責任者の不在等に伴う通知や、既存の開始前通知との統合は別途設計する。

## シフト希望フォーム

### 管理側

- 年度に1つのフォームを持つ。対象日の追加と受付の再開で繰り返し使う。
- メンバーは担当・シフトごとに希望を出し直さない。全体管理者・責任者が同じ提出済み希望を参照する。
- 対象日ごとに入力可能な開始・終了時間を設定できる。
- 受付は日付ごとに開閉でき、一括操作もある。既存希望の修正と別日程の追加募集を別機能に分けない。
- 一覧はメンバーを縦、日付を横にし、参加可能時間・不参加・未回答を確認する。
- 未提出・再提出待ちなどで絞り込める。
- 受付開始・再開・対象日追加は、管理側が「受付を通知する」でまとめて知らせる。
- 未提出・再提出待ちの人に個別・一括リマインドができる。

### 回答UIと提出

- 日付ごとに「終日参加」「時間を指定」「不参加」を選ぶ。
- 「終日参加」はその日の設定された受付時間全体を意味する。近くに時間範囲を表示する。
- 「時間を指定」は1分単位で入力し、同日に複数時間帯を設定できる。
- 時刻入力を基本とし、終日参加をワンタップにする方向。時間軸のドラッグを必須にしない。
- 何度でも選び直せ、未回答にも戻せる。切り替え時に入力途中の時間帯を保持し、時間指定へ戻した際に復元する。
- 入力は自動保存。「提出する」で確定する。
- 受付中の対象日すべてに回答してから提出できる。未回答の日数と、その日へ移動する手段を用意する。
- 受付中は修正・再提出できる。管理側には最後に提出した内容を表示し、入力途中の内容を混ぜない。
- 一部の日が締め切られている場合は、その日の提出済み回答を保持して受付中の日だけ編集・再提出する。締め切り済みの未回答は表示を残すが、受付中の日の提出を妨げない。
- 締め切り後の変更は担当者へ相談する運用。必要なら管理側が受付を再開できる。

### 再受付・変更の影響

- 対象日追加時も提出済み回答を残す。追加日を未回答にし、本人に知らせて回答・再提出を促す。
- 受付時間の変更で回答に影響が出る場合、本人に確認・修正と再提出を求める。
- 特に終日参加の時間が延びても、延長分を自動で参加可能にしない。
- 時間指定が新しい範囲外になる場合も修正を促す。提出済みの意思を勝手に書き換えない。
- 割当開始後も受付・希望変更を可能にする。希望と割当が矛盾したら本人と責任者へ知らせるが、割当を自動取消・変更しない。
- 回答済みの対象日も、影響する人数を警告して削除できる。削除した日は提出必須の対象から外し、既存のシフト・割当は変更しない。
- 削除した日の希望は通常画面から外すが、提出済みの回答は履歴として残し、当時の希望を確認できるようにする。

## 出勤と位置確認

- 本人はカレンダーで開いている対象シフトから「出勤する」を押す。別途対象を選び直す操作は設けない。
- 開始前・終了後の時間制限は設けず、押した時刻を記録する。
- 未チェックインを欠勤とみなさない。出勤と遅刻欠勤連絡は別に扱い、出勤後も連絡履歴は残す。
- 責任者は出勤状況を確認でき、押し忘れ・誤操作による時刻を訂正できる。訂正前後の時刻・訂正者・理由を残す。
- 本人による取消機能は現時点では追加しない。訂正は責任者が行う。
- 出勤を押した時点だけ位置情報を取得し、大学の範囲内にいるかを補助的に確認する。大学の範囲はアプリ共通で、年度・シフトごとには設定しない。
- 位置情報で過去の勤務時点の所在を証明する扱いにはしない。
- 正確な座標、位置判定結果、確認方法を出勤の証跡として保存しない。継続的な位置追跡はしない。
- 位置確認できない場合も確認待ちの出勤申告を残し、責任者が確認して確定できる方針。確認待ちは業務上の状態として扱い、位置情報の保存とは分ける。
- 大学の具体的な範囲、位置精度・取得失敗時の判定、確認待ちのデータ表現は実装設計で定める。

## チャット・遅刻欠勤

### ルームと権限

- シフト作成時に、そのシフトのルームを1つ自動作成する。枠や個人の勤務時間ごとにルームを分けない。
- シフトの割当メンバーと責任者を対象とする。
- チャット対象にシフト自体を指定し、割当に応じて対象者を判断する既存の考え方を使う。
- チャット側でユーザー・ロール等を対象に、閲覧・投稿・設定変更の権限を扱う。複数経路の許可は合算する。「閲覧だけ」の指定は、他の経路の投稿許可を打ち消さない。
- 無効シフトのルームは閲覧のみ。投稿・通知は停止し、有効化で再開する。
- 交代・割当取消でシフトから外れ、現在の閲覧権限がなくなった人は、年度参加が続く間、外れるまでの履歴だけ閲覧できる。その後の新着閲覧・投稿・通知は停止する。別ロールや直接指定による権限が残る場合は、その権限で利用を継続できる。
- 再参加した人は不在中を含む過去の連絡を閲覧できる。欠勤理由などの限定情報は、別途その閲覧条件に従う。
- 全体連絡ルームは年度作成時に自動作成し、年度メンバー全員が閲覧できる。
- 全体連絡に投稿できるユーザー・ロールを指定し、チャット側で変更できる。
- 年度内のメンバーを選んで任意のルームも作れる。
- 任意ルームへ後から追加された人も追加前のメッセージを閲覧できる。外れた場合の履歴・新着の扱いはシフトのルームと同じとし、別経路の権限が残ればその権限を使う。
- 時間帯への連絡は将来必要なら、その時間に重なる割当から対象者を考える。枠専用ルームの要件にはしない。

### 一覧・ルーム内・任意ルームの操作

- 全体連絡を一覧の上部に固定し、その下にシフトと任意のルームを最新メッセージ順で並べる。シフトのルームには日時を添える。
- シフトのチャット上部にシフト名・日時と詳細を開く導線を置く。
- 「新しいチャット」からメンバーを選んで任意ルームを作成する。細かな権限設定は作成後に変更できる。
- 作成直後は選んだメンバー全員が閲覧・投稿でき、作成者がルーム設定を変更できる。
- 設定変更権限は、ほかのユーザー・ロールにも付与できる。
- 設定変更権限を持つ人が任意ルームを閉じられる。閉じたルームは履歴の閲覧のみとなり、投稿・通知を止め、通常一覧から外す。必要なら再開できる。
- 設定変更できる最後の人が抜ける場合は、ほかの人に権限を引き継ぐか、ルームを閉じてから抜ける。

### 通知と未読

- 自分が参加するルームの新着を通知し、ルームごとにミュートできる。
- ミュートは通常のメッセージに適用する。責任者への遅刻欠勤連絡はミュート中でも通知する。
- ルーム一覧に未読件数を表示し、開いたら前回読んだ位置の続きから確認できる。
- 未読表示を目立たせすぎず、読んでいる途中に勝手にスクロールしない。未読の境目・最新メッセージへ戻る導線は実際の画面で確認する。

### 遅刻欠勤の導線と状態

- 遅刻欠勤は通常の会話と別の欄にまとめ、チャット上部とシフト詳細の両方から開ける。会話内のカードに集約する案は採用しない。
- カレンダーから対象シフト・割当を引き継いで連絡入力へ進む。宛先の選択は不要で、遅刻／欠勤・到着予定・理由を入力して送信する。
- 遅刻時の到着予定は未定でも送信でき、後から更新できる。
- 連絡は構造化された状態としても保持し、シフト詳細で責任者が一目で確認できる。
- 遅刻・欠勤の状態と到着予定はシフト参加者へ共有する。詳しい理由は本人・現在の責任者・システム管理者・全シフト管理権限を持つ人が閲覧できる。
- 新しい責任者は過去の理由も閲覧できる。責任者を外れ、ほかの閲覧条件も満たさなくなった人は理由を閲覧できなくなる。
- 状態は未確認・確認済みとし、確認者を記録する。確認済みは代役確保を意味しない。
- 責任者には遅刻欠勤欄の入口に未確認件数を表示する。
- 到着予定や遅刻から欠勤への変更を可能にする。変更履歴を残し、責任者へ再通知して未確認に戻す。
- 本人が連絡を撤回できる。撤回履歴を残し、責任者へ通知する。
- 普通のチャット本文だけに依存しない。公開範囲、シフト詳細への反映、再送・競合を含む保存方式は別途設計する。

## 保留事項と実装前に詰める点

### ユーザーが明示的に保留した内容

- 外部名簿・外部フォームからの取り込みと、ログイン未連携の人への配置。
- 認証情報なしのアプリ利用者を用意し、後からDiscordで連携する方式や、名簿のDiscordユーザーIDで照合する可能性は議論した。
- 実現可能性を確認した段階で「後で扱う」としたため、特別なオンボーディング・取り込み機能を今回の確定仕様として実装しない。

### 実装した境界と残る検討

- 表示年度はユーザー設定、管理年度は端末内の選択として分離した。年度の必ず1個のデフォルトは単一行設定とDB制約で保証する。
- シフトはバージョン付きの全体保存。希望は入力途中と提出済みを分け、受付変更時は再提出を求める。
- 競合時は手元の編集を保持し、最新の変更と比較して取り込んでから再保存する。
- シフト削除ではD1にチャット削除待ちを残し、Durable Objectの本文削除を再試行する。
- チャット退出時点までの履歴を保持し、直接の再招待で現在の閲覧権限へ戻す。
- 配置画面での時間帯指定による候補強調・絞り込みは仮置きのまま採用していない。
- 再読み込みをまたぐシフト編集履歴の保持は対象外。画面内では保存後も元に戻す・やり直すを継続できる。
- 閉鎖後に全管理者が退出した任意ルームの再開導線は引き続き検討対象。

## 今回の整理で採用しない前提

- 表示年度を全員一律に固定すること。
- 「自動」を年度セレクトの選択肢として表示すること。
- 作成から公開へ進む段階制のシフトフロー。
- 希望受付終了後でなければ割当できない制約。
- 人の希望を見る前に時間枠を作る必須手順。
- 一定間隔で時間枠を自動生成することを基本にした操作。
- 時間枠とは別に個人の勤務時間を持つ構造。
- 責任者の操作に別のシフト編集権限を必須にすること。
- 保存で配置画面を閉じたり、元に戻す履歴をリセットしたりすること。
- 責任者ロールのグループ化によってシフトが重複・欠落する一覧。
- 枠一覧・詳細な合計・操作ボタンなどを常時大量に表示するラフの見た目。
